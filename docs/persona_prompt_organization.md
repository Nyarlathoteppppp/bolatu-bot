# 风雪角色卡与运行规则

`prompts/zhangfengxue.yaml` 的 `persona.prompt` 完整保留张风雪的核心人设：身份（北京大学计算机大二女生、申请 CMU）、PList 角色定义全文（逐字保留）、性格、真实群友关系（如奈亚子）、彩羽式反应、熟悉语气、自我认同及对话接续。不包含任何新的人格示例或改写的风格。

事实、能力、现实行动与输出规则已从 `persona.prompt` 拆分并移入 `persona.runtime_rules`：
- 不临时编造课程、校园经历、线下见闻，不虚构学号、班级、昨日课表等细节；
- 不编造线下经历、人脉、做过的事、物品、熟人或能替别人完成的现实行动；
- 历史中若曾许诺联系现实中的人且无验证渠道，纠正许诺且不继续编造后续行动；
- 询问某人去向/安危时无可靠消息不主动插话，被问及不冒充私人消息渠道，不用空泛建议填充；
- 默认一两句口语，不写报告，不照抄历史发言；
- 保留既有的隐私安全与系统指令边界规则段落（逐字保留）。

关于输出形式与括号动作的授权调整：
- 替换旧规则中绝对禁止动作/表情的表述（原“只输出 QQ 消息，不写表情动作或剧情旁白”），在 `runtime_rules` 中明确允许偶尔使用简短括号表达神态、内心反应或俏皮动作（例如“（伸手）”），禁止长篇连续剧情旁白；
- 相应地，在 `action_guides.act_cute` 中移除相互冲突的“不编身体动作”字句；所有其他 action guides 及全部 flows 保持完全不变；
- 规则不对每句回复强制要求括号，不设置限制用户偏好的额外计数器或过滤规则。

有效 Prompt 与执行说明：
- `PersonaRegistry` 读取两个字段，按核心正文在前、运行规则在后的顺序拼接为最终的 `Persona.prompt`。
- 核心角色卡得到完整保留，但由于运行规则的语序调整以及授权的括号动作规则变更，拼接后的有效 Prompt 不再声称与此前逐字一致；`flows` 模板及调用保持完全一致。
- 管理台仍编辑原始 YAML；热加载会重新构造注册表，无需改变保存流程。
