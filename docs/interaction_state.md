# 有消息依据的短期互动状态

## 输入和存储

`interaction_state.py` 使用 `MemoryStore` 的同一 SQLite 连接，新增 `interaction_events` 表。表只保存消息关联、接话依据、字面反馈类别和生成所用消息窗口的读取时间；正文仍引用 `messages`，不复制长期记忆。

- 群消息入库后记录 QQ 回复边和已有的点名判断。
- `bind_discourse()` 消费本轮唯一 `DiscourseState` 的对象判断和已解析 `CONTINUATION` 来源。指物、同谓词、省略解析失败均不会单独合并互动。
- 显式 QQ 回复优先于隐式接话；无法找到原消息时保留回复 ID，不猜对象。
- 普通回复分段发送，每段只有在获得发送回执且入库后记录 `sent`。附带表情包也记录实际发送；草稿、审批等待、失败或未知结果不算发出。
- 手动广播、后台主动发言缺少具体触发消息，不会被当作某个问题的回复。

## 当前视图

复用群聊现有 `context_limit` 消息窗口，加上当前消息和直接引用的父消息。读取当前消息的祖先链以及窗口内对当前消息的回复，不引入祖先的其他回复分支，也不重放持久化的整棵历史树。

结构化 JSON 包含：

- 消息的 QQ ID、数据库 ID、说话人、时间、真实文字段、回复边及其来源。
- 点名对象判断及字面疑问、纠正、语气反馈、结束标记。
- 尚无直接 bot 发送记录的疑问句 ID；这表示发送事实，不表示问题已解决，也不要求开口。
- 最近实际发送与生成所用消息窗口的读取时间。该窗口若早于当前分支的反馈，会列出相应反馈 ID；新反馈保留。
- 结束标记只关闭该说话人在当前祖先链上的问题，不能替其他群友结束提问。

没有文字段的历史入库消息不从引用包装文本推断语气；其 `text_provenance` 为 `unavailable`。字面类别不是心理判断，结构中不保存推测情绪、亲密度、校园经历或待办承诺。

格式化数据附入已有 `speaker_context`，沿现有调用传给决策、动作选择、回复生成和 critic。没有新增模型请求，没有重写角色卡，没有新增定时发言。

## 生命周期与验证

消息关联可跨进程重启保留，但每轮注入内容由当前消息窗口限定。清空群消息时同步清空关联表。

测试覆盖 QQ 回复和分支隔离、解析成功与失败、原始文字段、晚到审批、部分发送失败、发送后通知失败、重复消息、重启与清空。回放为离线消息与模拟发送回执，没有向 QQ 群发送测试文本。拟人表达的改善仍需真实对话观察。
