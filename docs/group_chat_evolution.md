# 群聊质量框架与演进路线

最后更新：2026-08-28  
状态：设计记录。除明确标为“已实现”的项目外，不能假定已在运行。

本文档记录张风雪群聊体验的长期优化框架，避免后续只改 Prompt、忘记后端状态和数据边界。

## 1. 当前已实现的基础

- OneBot MessageChain、原始事件、发言人、引用和艾特关系保存。
- buffer、工作强度、低价值拦截、频率控制、禁言状态和发送队列。
- decision 负责社交动作，tool_router 负责搜索/行情/网页工具。
- RAG、memory atoms、群友画像、黑话、原文语料和风格规则分别保存。
- 发送后为相关群友打开 90 秒 followup 窗口。
- WebUI 可查看 Trace、记忆、RAG、模型和 Token。

## 2. 体验目标

机器人不是逐句问答机。一次群聊行为应满足：

1. 分清谁在说谁、谁回复谁、是否在说风雪。
2. 只在能增加聊天价值时插话。
3. 不用过期候选回复已经转走的话题。
4. 不重复同一种开头、口癖、主动话题或表情。
5. 长期记住稳定关系，但不会把反串和互损写成事实。

## 3. 后续演进项

### 3.1 发送前二次校验

**目标：** 消除“候选生成慢，发出时已经过了一轮”的迟到回复。

在候选生成完成、发送前读取最新 2-3 条消息：

- 当前话题已明显转移：丢弃候选。
- 原触发人已自行收尾或离开：丢弃候选。
- 有人正在直接回复风雪：允许保留，但需要重新标注 reply target。
- 只更新状态，不二次调用 LLM。

指标：`pre_send_revalidated`、`pre_send_stale_dropped`、候选生成到发送的延迟。

### 3.2 短期对话线

**目标：** 让被艾特或接话后的风雪自然续聊，而不是把所有“你”都误会成自己。

以群为单位维护短期 dialogue thread：

```text
participant_user_ids
opened_by_message_id
topic_hint
bot_last_message_id
expires_at
```

只根据结构化 reply / at、机器人刚发言和明确称呼开线。默认 90 秒，延续则续期；其他成员插话不自动加入。decision 读取这份事实状态，但仍可输出 ignore。

### 3.3 话题冷却和多样性

**目标：** 避免机器人反复主动聊同一题材，例如某部动画、学校或股票账户。

- 记录主动话题 `topic_id`、时间和结果。
- 24 小时内同主题降权，72 小时内禁止重复抽到完全相同的细主题。
- 最近三次主动话题必须尽量属于不同大类。
- 话题无人接、被拒绝或引发误解时，延长该题材冷却。

### 3.4 句式与口癖去重

**目标：** 避免“好家伙 / 这就 / 风雪觉得”等模板连续出现。

发送前将候选与机器人最近 10 条文本比较：

- 高风险开头词和固定句式降权。
- 字符串/语义相似度过高时直接丢弃候选。
- 这是一层表达质量过滤，不替代人格 Prompt。

### 3.5 记忆生命周期

见 [`memory_lifecycle.md`](memory_lifecycle.md)。核心是热记忆、周回忆、月回忆和独立 memory atoms，而不是无限增长的 active segment summary。

### 3.6 审批反馈

审批反馈目前不是主学习通道：实际使用频率低，QQ 英文/编号工具不适合日常维护。

保留它作为可选人工纠错：

- 人工确认的优质发言可作为高权重样本。
- 不准奏原因可用于定位具体问题。
- 不以审批通过率自动改变人格或 action 权重，除非未来重新启用一套中文 WebUI 反馈流程。

### 3.7 群聊健康面板

在现有 WebUI 上增加主群概览：

- 收到消息、进入 decision、should_reply、实际发送比例。
- 回复对象与 action 分布。
- 被前置拦截、被 cooldown 延后、被发送前校验丢弃的原因。
- 主动话题分类与冷却状态。
- 模型延迟、失败和 fallback 次数。

调活跃度、频率和 Prompt 前先看这些数据，不根据一两条聊天印象盲改。

## 4. 优先级

1. 发送前二次校验。
2. 短期对话线。
3. 记忆生命周期。
4. 话题冷却与句式去重。
5. 健康面板补充指标。

除非当前有明确故障，不建议用“增加 LLM 调用次数”解决以上问题。优先用结构化状态、索引和确定性后端规则。
