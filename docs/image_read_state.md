# 图片接收、识别和后续追问

## 原来的断点

群聊入口先等待图片识别，再保存消息。另一条消息可以在这个等待期间进入群聊处理锁，因此“这个图什么意思”的上下文中没有原图。入口识图又只检查当前消息的 image segment，引用图片的纯文字追问无法调用已有的引用识图能力。私聊合并多条消息时只识别最后一条，前面的图片也会漏掉。

## 现在的链路

1. 图片消息通过消息去重后，在第一次网络等待前保存原始 segment、QQ 消息 ID 和事件时间。
2. `ImageReadStateStore` 用数据库消息行 ID 关联接收和识别结果，状态为 `received`、`reading`、`ready`、`unavailable` 或 `skipped`。结果不会插入一条新的用户消息，也不会改变原消息时间。
3. 同一来源的追问复用正在运行的识图任务；同一图片在多个来源中出现时，`ImageOcrService` 使用已有的图片缓存 key 共享识别调用。单条消息取消不取消共享工作，清空上下文和进程关闭会清理任务。
4. 历史同步保留原始 segment；旧历史记录缺少 segment 时按同群同源消息补齐，保留原记录、文本和时间。引用消息先从当前群/私聊的原始记录取图片，缺少原始记录时使用已有的 OneBot 引用读取。纯文字引用也进入识图入口。
5. 不带引用的“这个图”先由唯一 `DiscourseState` 解析来源，再读该来源的结果；下游不选择“最近一张图片”。解析歧义或没有绑定时不强行选图。解析器把已绑定的真实图片计入 `media_present`。
6. 识别状态仅注入当前聊天上下文，`MemoryStore.recent_messages()` 保持原始记录语义，后台学习不会把“正在识别”作为用户发言学习。完成后的实际识别内容仍按现有媒体上下文方式保留。
7. 私聊准备阶段处理缓冲中较早的图片；最新一条为图片引用时，也读取引用内容。

已有 URL/path 可用时先识图，成功后不再额外调用 `get_image`。没有可用结果时保留已有的图片位置读取和 provider 回退。多图部分识别成功时保留真实图片序号，以及图片总数和识别数量。

## 生命周期

识别结果和接收事实持久保存；`reading` 由当前进程的真实运行任务提供，数据库等待期间仍保存 `received`。重启后没有运行任务就不会声称还在读图，另一个数据库连接也不会重置正在执行的任务。清空上下文会同时清除该会话的图片状态。

识图模型本身仍需要响应时间。本次处理接收事实、任务复用和结果关联，不保证即时得到图意。

## 验证

`tests/test_image_read_state.py` 覆盖慢识别与跨用户追问、取消一个等待者、跨群同图共享调用、空结果、重启、清空上下文、多图绑定、统一媒体状态、纯文字引用、入口首次等待前可见性、URL 无额外 API 往返和部分识别序号。`tests/test_private_message_stages.py` 覆盖私聊图片与问题连续发送，以及文字引用图片。
