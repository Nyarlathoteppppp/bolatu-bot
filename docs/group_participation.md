# 群聊接话与模型配置

## 时机判断

1. 直接艾特、回复风雪和已确认的短期接续，沿用本地处理，不参加随机抽样。
2. 短确认、纯笑声等低价值消息在入口过滤。JEV 明确判断沉默或回答时，不再付费调用 LLM 判断一次。
3. JEV 的 `timing_route` 判断参与机会，`to_other` 判断听话人。这两个问题不能互相替代。
4. JEV 认为有可选接话点、但现有规则尚未确认时，进入 LLM 复核。`llm.interjection_review_probability` 控制送审比例，当前为 0.70；它不是所有消息的回复概率。
5. LLM 只决定参与方式和具体 `reply_angle`。生成器结合该方向、已解析的听话人和实际发送过的互动状态生成回复。没有发送的接话计划不会写成已发生的互动。
6. 对别人的公开玩笑可以旁观加入；私人问题和约定不能代替被问的人作答，也不能因此执行对方指定的工具任务。

JEV 不可用时仍沿用既有 LLM 判断回退；因此异常期间 LLM 判断次数可能增加。明确的延续仍需有当前消息依据，不能因为互动窗口存在而强行追问或继续旧梗。

## 同时艾特

- 每群串行生成；新艾特不能越过已有待处理艾特。
- 提取最早的艾特及该用户前后连续的消息；不同用户之间的消息不能跨越合并。
- A1、B1、A2 的处理顺序仍是 A1、B1、A2，触发人、引用和来源 ID 随各自批次保留。
- “搜一下”遇到正在生成或排队的轮次时正常入队，不取消正在生成的任务、不提前取走缓冲。
- 普通消息仍使用原有缓冲机制；艾特优先于缓冲区里其他人的普通消息。

## 模型

回复、时机复核、其他文本任务、后台记忆和复盘默认使用 `lingsuan/gpt-6.1-sol`。回复请求 `reasoning.effort=medium`；判断及其他任务请求 `low`。搜索仍使用原 DeepSeek 路由，图片识别仍使用 DS 官方并保留原读图回退。

灵算主路由失败时只回退 DS 官方。既有 QQ 和管理台模型选择仍可覆盖默认配置；部署这次默认变更时，需要同时恢复文本路由和后台模型默认值。

角色核心卡措辞保持原样。运行规则允许风雪虚构自己的日常和小反应并保持连贯；真实群友的经历、外部事实、工具结果和现实行动承诺仍须有依据。
